# 安全边界与限制

Permsift v0.1 是面向可信或审核过的项目的权限实验工具。它依赖 macOS 和固定版本 Sandbox Runtime 执行隔离，不是经独立审计的恶意代码分析系统。

## 固定策略

- 文件读取：拒绝 /Users、当前用户家目录、原项目和实验管理目录；重新允许本轮工作区、缓存和临时目录。若 Node 安装在家目录内，则允许对应的 Node 安装树。系统路径的读取仍较宽。
- 文件写入：可变授权只能落在本轮目录的批准范围内。原项目、配置、limits 和报告位置固定禁止写入。
- 后端的 /tmp/claude 和 /private/tmp/claude 默认写例外被显式禁止。设备和标准输出等固定写权限仍存在，完整生效设置保存在 evidence 中。
- 网络：allowedDomains 为空，关闭本地绑定、Unix socket 放行、Apple Events 和弱隔离选项。SRT 可能为其拒绝所有目标的代理保留本地通道，这不等于进程不存在任何网络相关系统调用。
- 环境：只向任务传递定义好的 PATH、临时 HOME、缓存路径、语言和 CI 设置；不继承宿主 token、NODE_OPTIONS、BASH_ENV 等。SRT 命令构造期间也移除会被其重新拼入命令的宿主 Java/Git/代理设置。

limits 中的 allowed_write_roots 是**可变目录授权**的最高范围，不是对整个操作系统全部能力的表达。工具不会声称后端固定基础权限已被最小化。

## 被测任务与可信执行器

实际命令在临时副本运行。配置、冻结输入、验证器、证据和最终报告由宿主执行器管理，不作为任务可写资源暴露。探针使用假秘密、随机标记文件和临时本地 TCP 服务。

宿主断言只使用内置解析逻辑，不执行项目提供的验证脚本。文件读取拒绝符号链接和特殊文件，并限制大小。输入快照拒绝外部符号链接，不复用原项目的可写硬链接。

测试报告由任务产生，所以不能防止恶意项目谎报“测试通过”。任务也应避免主动攻击验证器、故意耗尽宿主资源或绕过进程组管理。对于这些行为，v0.1 没有作出隔离完整性承诺。

## 探针结论的范围

宿主先确认资源存在及端点健康，再检查沙箱内操作结果。EPERM/EACCES 可作为拒绝证据；夹具缺失、探针无法启动、端点停机和不明确超时均不能算通过。

测试只覆盖实现的访问路径。一个本地 TCP 连接被拒绝，不能证明 IPv6、UDP、DNS、系统服务或所有 IPC 通道都被完整验证。读写探针也不构成沙箱无逃逸的证明。

## 进程与资源

每个工作负载拥有独立进程组，正常退出、超时或取消时终止该组，避免普通后台子进程污染后续实验。故意调用 setsid、守护进程化或借宿主服务启动独立进程，超出支持的工作负载约定。

任务日志、输入快照、断言文件和输出扫描有大小限制，但没有提供内核级 CPU、内存、磁盘配额或完整系统调用过滤。时间预算包含阶段检查和进程超时，宿主复制与后端初始化不能立即抢占。

## 运行环境与证据

macOS Seatbelt/sandbox-exec 的行为可能随系统版本变化，应在新环境先运行 doctor 并完成集成测试。v0.1 不在不支持的平台上静默退回普通执行。

本地 JSON 报告没有数字签名。被测沙箱进程被禁止写报告，但同一宿主用户的其他进程仍可修改报告。日志可能包含项目输出，不应未经检查上传到公开 issue。

发现缺陷时，应先用假数据创建可重复案例，记录系统、Node、SRT 和 Permsift 版本。项目尚未建立独立的漏洞披露邮箱；公开讨论中不要附真实凭据。
