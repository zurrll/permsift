# 后续路线

## 已实现的 MVP

macOS 单后端、固定断网、可信场景和写权限上限、干净快照、逐项撤销与目录缩小、恢复复测、正向断言、反向探针、证据报告和真实集成测试。

与早期草案相比，v0.1 明确将环境变量设置固定在执行器中，并使用小型结构化测试结果格式。运行记录按进程保留生效后端配置；读取权限没有参与自动搜索。

## 继续验证使用价值

v0.2 增加了三个可运行的代表项目及 Permsift 自身构建验证，记录运行次数、耗时、最终范围与失败证据。继续收集第三方项目的配置成本、排查时间和依赖升级后的回归定位效果，依据实际摩擦排序后续工作。

## 当前输入与搜索范围

用户提供本地项目、任务命令、成功断言、每个任务的初始目录写权限与可选项目读取权限，以及独立的权限与实验预算上限。Permsift 在项目副本中验证这些任务，为每个任务输出经过复测的配置。

v0.2 可以删除整个写权限，也可以将父目录写权限替换为自动生成或手工声明的子目录组合。自动发现覆盖工作区、缓存和临时目录，且有深度与目录数限制。v0.3 增加项目文件/目录读取收缩，运行时、缓存和临时读取保持固定，网络保持关闭；任意原始沙箱配置仍不在输入范围内。

结果只相对于给定任务、输入、断言和候选操作成立。默认系统与运行时读取权限、设备与标准流权限，也不在本轮最小化范围内。

## 已实现 v0.2：自动生成候选并解释结果

目标是让用户主要描述“运行什么、怎样算成功、最多允许什么”，减少手工猜测输出目录的成本。保留手工候选作为补充，所有自动候选仍必须在用户给出的权限上限内。

1. **生成候选目录。** 从已验证的基线运行中的文件变更、项目目录结构和已有失败证据生成候选，逐层尝试父目录到子目录的替换。限制目录深度、候选数和实验预算，避免大型依赖树造成搜索爆炸。
2. **保持撤销复测。** 文件变更只能作为线索：临时文件可能已经删除，某次任务也可能只覆盖一条分支。观察到访问不代表权限必需，没有观察到也不代表可以安全删除。每个建议仍须实际收缩、执行任务并验证；失败或未知后恢复复测。
3. **解释失败。** 报告并列展示被删规则、被拒绝访问的路径与操作、命令错误、失败断言和恢复结果。日志缺失时明确标为证据不足；恢复成功支持本次比较，不自动证明所有失败都由权限造成。
4. **接入真实测试结果。** 支持受限 JUnit XML，校验预期测试项、失败、跳过和报告新鲜度，并用 Node 原生 JUnit reporter 验证。继续使用明确的产物断言验证构建成功。
5. **验证三个代表项目。** 覆盖依赖已准备好的测试项目、构建项目，以及需要缓存或临时目录的项目。记录配置工作量、运行次数、总耗时、最终权限、必要权限被拒绝后的恢复证据。

已覆盖的完成标准：代表项目不填写 `narrower_candidates` 也能得到经过最终复测的更小写权限；必要权限被删除时保留拒绝或失败证据与成功恢复；缓存、临时写入和准备变化导致基线失败的案例有测试覆盖。候选来源与未覆盖范围写入报告。实测记录见 [validation.md](validation.md)。

## 后续扩展顺序

### 已实现 v0.3：项目读取权限

支持显式项目读取上限、文件与目录自动候选、撤销恢复、读写联合搜索和真实边界探针。固定系统/运行时、缓存和临时读取，报告注明实际范围。真实测试确认写授权不隐含文件读取；文件目标规则精确，前后探针保持同一文件/目录语义。固定提交 clsx 完成原始构建、产物断言及导出策略重放。详见 [读取说明](read-permissions.md) 与 [第三方项目](third-party-clsx.md)。

下一步先收集更多项目与升级回归，再按实际需要增加明确的外部输入、改进枚举范围和搜索成本。

### 已实现 v0.3.1：减少重复搜索

同级授权成组尝试，失败恢复后拆分；已尝试操作按轮复查，同一轮的相同明确失败只作为拆分线索。写权限没有变化时不再重复已完成的读取搜索。最终规则下已实际完成剩余比较时省略重复收尾轮。clsx 搜索从 190 个 trial 降至 89 个，最终权限相同；三个小型代表项目次数保持不变。详见 [搜索效率](search-efficiency.md) 与 [实测记录](validation.md)。

### 已实现 v0.4：规则回归检查

使用历史 verified 报告，在当前冻结输入下验证旧规则；兼容时不重新搜索，失败时做宽规则对照和有限补充。报告保留输入与环境变化、当前断言、实际失败和恢复证据；验证通过的建议导出供审阅。已覆盖代码新增输入、真实 clsx 新增依赖、普通代码错误及目录准备变化，详见 [回归检查](regression-checks.md)。

### 已实现 v0.5：工作区克隆、安装依赖与网络权限

工作区优先使用写时复制，保留文件独立性和不支持磁盘的安全回退；回归阶段也从共同输入克隆并核对哈希。npm ci --ignore-scripts 安装支持固定锁文件、精确域名集合、独立可信上限，以及冷缓存和固定暖缓存分别验证。域名候选先搜索，随后尝试写权限，并按变化复查；安装后断网验证实际依赖和产物。网络异常保持 unknown，日志线索不自动加权为必要域名。域名升级也接入 check。详见 [快照工作区](snapshot-workspaces.md) 和 [安装说明](dependency-install.md)。

现有后端提供读取规则和域名过滤机制，因此可以先扩展 Permsift 的规则模型与验证流程，继续复用后端。具体行为仍应以锁定版本的代码和真实集成测试为准：[Sandbox Runtime 官方说明](https://github.com/anthropics/sandbox-runtime)。

### 已实现 v0.6：分阶段权限与安装状态复用

显式配置将安装写规则与离线任务读写分开执行；安装规则固定后冻结安装状态，任务候选使用独立副本并按包收缩生成依赖读取。最终重复验收、run 和 check 仍重新安装，报告记录真实安装与复用次数。旧配置保留共用写行为；首版只支持安装/任务两段和场景内复用。见 [分阶段说明](staged-permissions.md)。

### 已实现 v0.7：中等规模验证与成本可见

固定 fast-glob 的编译、246 项单元测试和构建 API，通过沙箱冷安装与固定暖缓存搜索验证；报告记录独占耗时和阶段停止原因。任务快照实验合并重复清单扫描，完整性核对及最终新安装保持。更大的依赖树也暴露出 32 条读取规则上限和配置适配成本，当前不据此扩张安装能力；详见 [实测方法](performance.md)。

### 回归检查、搜索效率与 Linux

继续收集第三方项目的代码与依赖升级，验证回归分类、建议范围和复审成本，再扩展模块解析线索。继续验证分阶段配置成本、包数量与哈希开销，按实际摩擦改进候选预算。安装器读取和生命周期脚本的单独权限阶段需另行设计，其他包管理器放在之后。测量不同规模项目的克隆、哈希和冷安装成本，控制候选调度。Linux 后端需要独立的能力检查、边界探针和真实集成测试，不能直接沿用 macOS 的验证结论。

可选的日志解释和 Agent 场景放在这些基础能力之后。

## 是否自研沙箱

自研后端不是必要里程碑。当现有后端的规则语义、可观测性或执行成本实际阻碍实验时，可以实现一个范围较小的后端。继续使用操作系统提供的隔离机制，并用同一套任务、断言和探针比较行为。

若以深入学习为目标，可以单独做基于 Linux Landlock 等机制的实验后端；不要把新的后端自动当作现有后端的安全替代品，也不需要为此重写隔离内核。
