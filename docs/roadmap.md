# 后续路线

## 已实现的 MVP

macOS 单后端、固定断网、可信场景和写权限上限、干净快照、逐项撤销与目录缩小、恢复复测、正向断言、反向探针、证据报告和真实集成测试。

与早期草案相比，v0.1 明确将环境变量设置固定在执行器中，并使用小型结构化测试结果格式。运行记录按进程保留生效后端配置；读取权限没有参与自动搜索。

## 下一轮先验证使用价值

选择三个不同的小项目，记录准备成功断言的成本、排查时间、实际减少的写入范围和依赖升级后的回归定位效果。依据遇到的摩擦排序后续工作。

## 当前输入与搜索范围

用户提供本地项目、任务命令、成功断言、每个任务的初始目录写权限，以及独立的权限与实验预算上限。Permsift 在项目副本中验证这些任务，为每个任务输出经过复测的配置。

v0.1 可以删除整个写权限，也可以将父目录写权限替换为用户在 `narrower_candidates` 中声明的子目录组合。它尚未自动发现候选目录，也没有导入任意沙箱配置的功能。读取权限由执行器固定，网络保持关闭。

结果只相对于给定任务、输入、断言和候选操作成立。默认系统与运行时读取权限、设备与标准流权限，也不在本轮最小化范围内。

## 建议 v0.2：自动生成候选并解释结果

目标是让用户主要描述“运行什么、怎样算成功、最多允许什么”，减少手工猜测输出目录的成本。保留手工候选作为补充，所有自动候选仍必须在用户给出的权限上限内。

1. **生成候选目录。** 从已验证的基线运行中的文件变更、项目目录结构和已有失败证据生成候选，逐层尝试父目录到子目录的替换。限制目录深度、候选数和实验预算，避免大型依赖树造成搜索爆炸。
2. **保持撤销复测。** 文件变更只能作为线索：临时文件可能已经删除，某次任务也可能只覆盖一条分支。观察到访问不代表权限必需，没有观察到也不代表可以安全删除。每个建议仍须实际收缩、执行任务并验证；失败或未知后恢复复测。
3. **解释失败。** 报告并列展示被删规则、被拒绝访问的路径与操作、命令错误、失败断言和恢复结果。日志缺失时明确标为证据不足；恢复成功支持本次比较，不自动证明所有失败都由权限造成。
4. **接入真实测试结果。** 优先增加一种常用的结构化测试报告适配器，例如 JUnit XML，校验预期测试项、失败、跳过和报告新鲜度。继续使用明确的产物断言验证构建成功。
5. **验证三个代表项目。** 覆盖依赖已准备好的测试项目、构建项目，以及需要缓存或临时目录的项目。记录配置工作量、运行次数、总耗时、最终权限、必要权限被拒绝后的恢复证据。

完成标准：至少一个代表项目不填写 `narrower_candidates` 也能得到经过最终复测的更小写权限；必要权限被删除时有可理解的拒绝或失败证据与成功恢复；缓存、临时写入和基线不稳定的案例都有覆盖。候选来源与未覆盖范围写入报告。

## 后续扩展顺序

### 读取权限

先针对项目输入和明确声明的外部输入搜索可撤销的读取授权，固定运行时必需读取，并把固定部分写入报告。需要验证现有后端的规则优先级、符号链接行为、启动依赖，以及“允许写入是否隐含部分读取”等语义。与写权限一起报告时，不能把只读收缩冒充为禁止访问。

### 安装依赖与网络权限

先支持固定锁文件、用户明确批准的域名集合，以及冷缓存和热缓存分别验证。尝试删除域名授权并重新安装，验证依赖实际齐全；拒绝未授权目标的探针和可用目标的对照检查也要一起加入。域名授权不自动等于 URL 路径、具体内容或供应链可信度约束。

现有后端提供读取规则和域名过滤机制，因此可以先扩展 Permsift 的规则模型与验证流程，继续复用后端。具体行为仍应以锁定版本的代码和真实集成测试为准：[Sandbox Runtime 官方说明](https://github.com/anthropics/sandbox-runtime)。

### 回归检查、搜索效率与 Linux

将已验证策略用于后续依赖或代码升级的回归检查：区分任务本身失败、权限导致失败和实验环境未知，再报告需要复审的权限变化。真实项目暴露出运行成本后，再优化快照复制和分组搜索。Linux 后端需要独立的能力检查、边界探针和真实集成测试，不能直接沿用 macOS 的验证结论。

可选的日志解释和 Agent 场景放在这些基础能力之后。

## 是否自研沙箱

自研后端不是必要里程碑。当现有后端的规则语义、可观测性或执行成本实际阻碍实验时，可以实现一个范围较小的后端。继续使用操作系统提供的隔离机制，并用同一套任务、断言和探针比较行为。

若以深入学习为目标，可以单独做基于 Linux Landlock 等机制的实验后端；不要把新的后端自动当作现有后端的安全替代品，也不需要为此重写隔离内核。
