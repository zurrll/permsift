# 第二轮：共同执行底座

这一轮把一次受控执行、流程决策和报告呈现分开。现有 CLI、配置、schema_version: 1 报告、导出文件名和退出码继续兼容；新增事实写入独立、版本化的 `executions/`，历史报告不会被改写。没有新增用户配置步骤。

## 职责与入口

| 模块 | 负责什么 |
| --- | --- |
| execution-request.ts | 将当前任务、具体授权、可信上限、运行条件和采集选择校验成可执行请求；建立模型中的任务、约定和方案 |
| execute-once.ts | 一次执行：独立副本、准备和产物刷新、安装、真实探针、离线任务、断言、变化和各来源记录 |
| execution-verdict.ts | 保留现有单轮 composite verdict 规则 |
| engine.ts | 普通运行和收缩流程：重复次数、候选、预算、恢复、快照选择/发布、最终验收及导出 |
| execution-phase.ts | 流程状态和精简执行结果；回归阶段直接据此判断，不再解释整份实验报告 |
| regression.ts | 旧规则、宽对照、确认、有限补充和重放建议的编排 |
| observe-command.ts | 每任务一次的观察流程及 usage 投影；直接使用阶段结果和来源记录 |
| model/native.ts | 由执行请求与真实返回事实构造模型记录，分别判断任务、边界和来源健康度 |
| execution-journal.ts | 每轮原始证据、模型事实及索引的保存顺序；保存失败不能进入后续接受或复用 |
| experiment-report.ts | 兼容报告类型和 Markdown 呈现，不启动任务 |
| installed-snapshot.ts | 捕获、完整核对、独立克隆的资源操作；实验内索引由流程管理 |

`executeOnce(request)` 接收展开后的具体任务与权限、冻结输入和准备目录、历史读取类型、安装条件、绝对截止时间与取消信号，以及明确的采集设置。历史模型允许 `not_saved` 等缺失状态，不能直接拿来执行；可执行请求要求完整命令、成功条件和具体授权，并再次核对可信读、写、网络与目录准备上限。

执行器不接收候选计数、搜索步骤、重复次数、报告对象、报告路径或快照发布库。阶段标签只由流程用来选择请求和标注来源，执行器内部不根据 `baseline`、`candidate` 等标签改变行为。资源操作包含文件 I/O；这不是纯函数。它返回有类型的过程、安装、检查、变化、实际发起命令、诊断和采集事实，不决定下一轮尝试什么。

`runExperimentWithFacts` 返回 `{ report, execution }`。`execution` 保存流程状态、冻结输入摘要、精简的单轮结果和观察记录；不会把每轮完整日志与文件清单长期留在内存。原 `runExperiment` 仍返回兼容报告，已有调用方无需修改。check 的实时路径使用 `phaseVerdict(execution)` 与类型化诊断；原 `regressionVerdict(report)` 仅保留兼容。observe 的任务清单、结果和来源记录也从 `execution` 获取，报告仅提供呈现所需的路径、时间和环境。

## 模型进入真实执行

每轮保存以下新增文件：

```text
executions/
  index.json
  <trial-id>.json
evidence/
  <trial-id>.json
report.json
report.md
```

`<trial-id>.json` 的 `kind` 为 `permsift_execution`。无声明记录使用 schema_version: 1；第四轮的可执行保护记录使用 schema_version: 2，model_version / identity_version 仍为 1。文件包含任务、保护约定、具体方案和一次执行证据，直接从请求与返回值构造。索引记录 trial、模型文件、原始证据及执行对象 ID 的对应关系。完整后端配置、探针过程、有限日志和文件变化仍在 evidence 文件中。

已知任务、约定和方案使用与旧报告适配相同的身份规则。读取目标在执行副本上解析后生成已解析方案；尚未到达解析步骤时保留缺口。输入、准备、安装和采集条件不混入任务成功定义。运行时固定读取与观察器内部写例外仍需查看后端事实，方案不是完整后端策略。

普通任务也保存实际发起的参数数组。TypeScript 观察追加的解释参数、观察预加载摘要和内部日志写例外进入执行条件；esbuild 的产物目录刷新仍只发生于观察模式。任务未到达、安装复用没有 installer 进程、来源未选择和记录不完整分别表达。命令已发起但没有取得进程事实时，保留未保存缺口，不能声称任务从未运行。

任务通过不覆盖边界或保护未知、来源不完整；流程通过也不意味着搜索完成。第四轮可选声明并执行保护目标，未声明配置保持原行为；成功报告不会产生“已采用基线”。第三轮 inspect 已可离线读取事实及工作流，第四轮沿用这一入口。详情见 [保护目标](protection-goals.md)。

## 安装与保存时序

安装快照继续绑定输入、环境、安装配置、安装授权、准备和 limits。请求还会校验选定快照的键符合这些条件。全新安装检查锁文件和清单不变；安装失败不执行离线任务。任务候选复用快照时完整核对源和克隆的 workspace/cache/tmp，仍有两次哈希、六次根扫描，不以路径或时间戳代替内容核对。

快照在安装完成后、任务和任务探针之前捕获。整个 trial 的任务、断言、边界检查通过，并且证据保存成功、预算仍有效后，流程才发布可复用状态。最终 repetitions、run 和 check 继续重新安装。捕获资源操作不负责从库中选择或发布快照。

每轮按以下顺序保存：原始 sidecar → 模型事实 → 原子替换事实索引 → 更新兼容报告。成功返回后才把结果交给后续流程、发布快照、删除本轮副本和继续下一轮。默认删除本轮工作树，独立安装快照继续保留到本次实验结束；保留工作区选项继续有效。

JSON 逐个采用临时文件加 rename，没有跨文件事务、fsync 或断电恢复保证。写入任一步失败会使实验 incomplete，停止下一轮且不发布快照。已写完的文件保留；可能出现尚未登记的 sidecar/模型文件，或事实索引已更新而报告 checkpoint 失败。原始事实与错误仍可人工检查，本轮不提供自动恢复继续实验。不能把一份完整的单轮事实误读成整条流程已完成。

## 验证与成本

新增单元反例覆盖请求缺失与越权、条件独立性、阶段请求、实际命令、目标类型和模型引用；保存失败分别在 sidecar、模型文件、索引及报告 checkpoint 注入。真实沙箱用例还故意阻断索引写入，检查只发生一次执行、原项目未改、事实可找回且没有推荐导出。

已有普通、回归、分阶段安装、模块、编译和打包集成用例增加模型文件及索引核对，复用原来的真实执行，不为这些核对另外安装或运行任务。对照稳定的授权、命令、任务/边界事实、恢复决策与重放结果，不要求时间、随机 ID 或临时路径逐字相同。原始报告仍通过第一轮适配。

本轮是职责整理，没有新的搜索算法、实验并发或跨次缓存，也没有声称实验次数减少。每轮多写一个精简事实文件并原子更新索引；换来的收益是执行事实、流程判断和报告呈现能够分别维护。验证实绩见 [环境检验](environment-validation.md)，后续摘要工作见 [整体计划](refactoring-plan.md)。
