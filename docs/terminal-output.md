# 终端展示

默认输出先说明结论，再列任务事实和结果位置。正常的小任务通常一屏可读；多任务/大量差异默认列前 24 行概览并明确提示还有多少行。异常提示、执行成本、采用/基线状态和解释范围不被这个概览上限截断。

```sh
# 查看已有结果，不重跑项目
node dist/cli.js inspect .permsift/manual-check
node dist/cli.js inspect .permsift/manual-check --details
node dist/cli.js inspect .permsift/manual-check --json

# 执行前的详细预览也不执行项目
node dist/cli.js explain --config examples/demo/permsift.yaml --limits examples/limits.json --details
```

`--details` 适用于 doctor、explain、run、tighten、check、adopt、observe、inspect、compare、diagnose。它会展开终端说明；执行命令仍会执行任务，所以看完结果后应使用输出中给出的 **只读 inspect 命令** 查看依据。`--json` 保持原有完整结构，与 --details 互斥；进度只写 stderr。

## 各命令的重点

| 命令 | 默认展示 |
| --- | --- |
| doctor | 内置环境任务和固定边界检查；不展示权限搜索字段 |
| explain | 命令、初始授权、成功检查、安装/观察安排和副本清理；静态通过不是任务通过 |
| run | 当前规则下的任务结果、固定边界与保护、可变授权和实验成本 |
| tighten | 验证结果、搜索停止原因、接受操作和候选范围；不声称全局最小或已经采用 |
| check | 输入和任务约定变化、当前验证、实际存在的复验阶段、建议与基线未自动更新 |
| adopt | 明确的用户选择、历史验证与理由；不声称当前项目已经重新验证 |
| observe | 任务结果、安装清单、Node 加载、已启用的编译/产物输入来源及覆盖限制 |
| inspect | 查看保存材料，原任务状态与材料完整性分别展示；包查询区分各采集来源 |
| compare | 输入/采集条件变化、分来源的包/文件变化；只读，不自动判定回归或依赖可删除 |
| diagnose | 按产物列成功条件诊断和发现，详细模式列扰动；格式拒绝不冒充内容验证 |

任务通过、固定边界通过、保护目标通过和依据完整是独立结果。声明成功但事实矛盾时会显示“结论存在冲突”；缺 sidecar 或来源不完整会显示缺口。安装失败后跳过的任务不计为任务进程记录，安装复用状态未保存时明确保留未知。次数是保留的执行事实，不是人类节省的时间。

权限行是生产者可变授权，不是后端全部运行时权限。@workspace 是隔离项目副本；旧式读取默认覆盖整个副本，显式空读取仍保留固定运行时读取。来源未采集、没有记录、记录的 0 字节贡献不能合并成“没用”。

## 进度与保留信息

交互终端在 stderr 更新一行，分别显示任务、验证/搜索/复验阶段、当前轮次、准备/安装/执行任务；宽度受终端列数约束。重定向时写普通行，不插入动态终端控制字符。原始逐实验授权进度仍可用执行命令的 --details 查看。

命令和包名、路径保持原文。常用状态与字段使用中文；详细模式中的原始检查说明、项目日志和来源问题保留原文。输出清理控制和双向文本字符，不提供交互确认或自动采用操作。

`src/terminal.ts` 从验证过的 ResultRecord 和既有 ResultSummary 生成展示，不解析英文段落猜测结论。`terminal.json` 是工作流结束时生成的展示缓存，避免 CLI 为打印摘要再次遍历全部执行文件；不参与策略接受或身份计算。**inspect 从原始保存材料重新解释，忽略展示缓存**，因此缓存不能覆盖证据结论。历史结果无需有 terminal.json，也无需迁移或重新执行。

summary.json、原始各类报告 JSON、模型身份、退出码和保存的 Markdown 保持原有接口。默认终端文本有意调整，不应作为机器协议解析。
