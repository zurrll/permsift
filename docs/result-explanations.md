# 结果解释与离线回访

第三轮让现有执行底座产生的记录更容易用于判断。权限路径解释“哪份规则经过了什么验证”，观察路径解释“哪个任务、哪个来源记录了什么变化”。它们共用保存和读取能力，继续保留各自的结论范围。

## 日常怎样使用

run / tighten / doctor / check / observe 完成后默认显示按命令组织的中文终端摘要，并生成 `summary.json`、`summary.md`。完整概览仍放到原有 report.md 或 usage.md 前面。`--details` 展开原始检查说明与依据；compare 指定 --output 时保存概览工件。原来的 report.json、usage.json、comparison.json、summary.json 和各命令 --json 格式不变。终端展示与进度规则见 [终端展示](terminal-output.md)。

```sh
# 阅读一轮已保存实验，不需要原项目
node dist/cli.js inspect .permsift/EXPERIMENT
node dist/cli.js inspect .permsift/EXPERIMENT/report.json --json
# 观察目录优先读取 usage.json，并核对其关联执行记录
node dist/cli.js inspect .permsift/OBSERVATION
# 单次原生执行；只能解释该次任务，不能推断整轮流程已完成
node dist/cli.js inspect .permsift/EXPERIMENT/executions/TRIAL.json
# 包的跨任务视图保持原样
node dist/cli.js inspect .permsift/OBSERVATION/usage.json --package glob-parent
# 已保存的依赖升级对比
node dist/cli.js inspect .permsift/COMPARISON/comparison.json
```

目录选择依次查找 usage.json、report.json、comparison.json。inspect 不写文件，不安装、不执行任务、不读项目目录；它也不会沿旧报告中的项目路径或 baseline 路径去寻找材料。项目移动或临时工作区清理后，保留的结果目录仍可阅读。

新概览格式为 `schema_version: 1, kind: permsift_result_summary`。JSON 包含流程原始状态、每任务 claims、候选 decisions、回归 stages、材料缺口和范围说明。每条 claim 都带文件与 JSON pointer 证据位置和一个具体行动；可用的模型对象身份一并保留。文字与 JSON 来自同一份解释结果。

## 先看什么

权限概览按任务显示当前变量授权、独立任务与固定边界检查、候选/恢复、搜索停止和生成范围。接受规则变更时保留 producer 的范围变化标记；移除已有覆盖的重叠授权与实际范围缩小分开表示，缺少标记就显示未保存。搜索耗尽只涵盖生成和配置的操作，不证明全局最小权限。

概览保留实验次数、报告中的安装/复用次数和已有耗时，帮助结合收益判断是否继续增加预算。耗时是原流程记录，概览生成在其后，不把呈现成本藏进“更少的实验次数”。显式读取同时显示文件/目录类型；有匹配的原生或修复复验材料时用这些材料补足类型，缺失时仍保留未知。

check 展示旧规则、宽对照、重新确认、恢复及修复复验的阶段表。阶段可以包含多次执行，表中的原始阶段 verdict 与独立任务/边界结果分列。修复建议即使验证通过，也没有自动采用记录。概览给出修复证据与审阅动作；第五轮可明确采用完整验证的 check 结果，无需为保存选择重跑任务。新执行验证仍需要可用项目和独立可信 limits。

观察概览按任务分别列安装清单、Node 模块记录、TypeScript 输入、esbuild 记录。版本变化保留包名和安装位置，文件解释、产物贡献和外部引用指向保存的比较。计数不能相加成“实际用了多少依赖”。0 字节是某个输出的已记录贡献；它与未采集、无记录和采集不完整有不同含义，不产生删包或撤权建议。

## 材料缺口怎样影响结论

| 情况 | 显示方式 | 可以继续判断什么 |
| --- | --- | --- |
| 工作流 verified，但搜索预算停止 | 两个结果分别保留；搜索显示 budget | 记录的最终规则验证与尚未完成的收缩分开审阅 |
| 候选失败，恢复通过且独立检查支持 | rejected / corroborated，并链接两次执行 | 这次配置比较中的依据，不是普遍必要性证明 |
| 恢复未知或前后材料矛盾 | unknown 或 contradictory | 先查恢复、任务和环境，避免可靠性不足的归因 |
| 报告保存 accepted/rejected，但未保存试验引用或明细 | reported_only | 原报告决策仍可阅读，不能补造比较证据 |
| 任务通过、模块采集不完整 | task pass 与 modules incomplete 分列 | 编译/打包等其他完整来源仍可使用 |
| 历史 usage 没有进程/断言/边界明细 | composite verdict 原样保留；独立执行 reported_only | 已保存的来源记录，不能补出独立任务/边界通过 |
| 回归子报告缺失 | 阶段原始 verdict 保留，独立结果 not_saved | 可看原来的修复建议；当前材料不足以复核全部阶段 |
| 只有一份原生 execution | 单次事实，workflow 未提供 | 不能由它推断搜索接受、恢复或最终重复次数 |

`analysis.status: complete / partial` 描述概览的问题是否有充分可读材料或仍有未完成部分，**不是任务是否通过，也不是安全总评分**。inspect 概览完整分析退出 0，部分分析或非法材料退出 2；任务失败也可以拥有完整分析。原来 inspect --package 的 0/1/2 语义保持不变，执行命令退出码也不改变。

not_saved 只表示当前材料中没有信息，可能是历史格式、样本投影或未提供伴随文件，不表示“原本检查过但丢了”。已记录的空授权或空来源列表则继续是空值，不补成未知。

## 读取与保存边界

- 旧报告通过已有五对象适配层进入解释器；搜索适配新增操作、前后授权和候选/恢复引用，缺失字段显式保留。
- 原生执行先验证版本、内容身份、任务/约定/方案引用、独立结论与来源结构，再核对 index、工作流、配置摘要及现有明细。矛盾材料拒绝读取，不混入可靠事实。
- 只加载当前目录下的常规 inputs、已声明的 evidence、executions/index 和固定布局的回归子报告。路径越界、链接伴随目录/文件、非普通文件和不匹配材料均拒绝。
- 每文件最多 32 MB；一次读取最多 4096 文件、128 MB，超过伴随读取预算保留缺口。引用和哈希核对提供内容一致性检查，不提供生产者认证。
- 索引里多出来而未进入工作流 checkpoint 的执行不能成为已完成流程的证据。没有被索引引用的松散文件不自动扫描；可显式选中一个原生文件检查。
- 保存失败可能留下非法索引等部分材料。自动概览此时退回只读工作流投影并明确记录 Companion validation failed；拒绝的伴随材料不用于推导结论。严格离线 inspect 仍会拒绝非法伴随材料。这保持原执行流程返回失败/不完整报告的行为。
- 概览在一轮流程结束后生成，不进入候选/恢复循环，不新增任务、依赖安装或项目快照。check 各子流程也分别生成概览；这些是读取和呈现成本，不是新的试验。

## 两条保存案例与验证

```sh
npm run results:verify
```

脚本通过公共 CLI 回放两条故事，PATH 中没有可用的任务、安装器或沙箱执行程序，校验源文件保持不变，记录 0 次项目执行、0 次安装：

1. **新增读取后的权限修复**：使用 permission-read-change 和 permission-repair-replay 的真实投影。旧/宽/确认/修复阶段 verdict 保留，缺失子报告和部分重放 sidecar 明示；不会把投影包装成完整证据或已采用基线。
2. **依赖升级后的产物观察**：使用 fast-glob 的前后保存记录，显示 glob-parent 5.1.2 → 6.0.2、包贡献和输出差异；模块与构建来源分别解释。比较记录之后可独立阅读，不再加载它记录的原 baseline 路径。

result-summary.test.ts 检查旧投影、恢复未知、独立边界失败、当前规则不匹配、原生内容/引用、缺失伴随材料、非法路径、不同冻结输入、来源不完整和 0 字节、公共 CLI 兼容及呈现一致。实际沙箱验证复用既有权限、回归和观察用例产生的记录，核对在线概览与离线投影一致，不为核对再执行一轮。

本机通过结果见 [环境检验](environment-validation.md)。这些验证证明读写和解释行为符合约定；跨主机实际 CI、独立使用者是否理解得更快仍未验证。

第四轮增加可选保护声明的逐目标、任务前后结果与额外检查成本，回归表格单独显示保护状态。没有声明的旧报告保持原解释；原生读取兼容无声明 v1 与可执行保护 v2。任务失败而保护通过，是两个可同时成立的结论；缺失目标和未到达阶段不能当成拒绝。详见 [保护目标](protection-goals.md)。

第五轮 inspect 同时支持采用包、存储目录及 current.json。摘要显示明确选择、理由/前序引用、逐任务历史验证条件与“本次未运行”，不把采用当成当前通过。check 摘要把精确约定变化、逐目标历史证据、本次阶段结果分开，删除目标不会续成当前保护。详见 [基线采用](baseline-adoption.md)。
