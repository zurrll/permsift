# 模块加载与解析明细分别保留

2026-10-05。node-module-load-v6 处理 [单文件 XO 对照](toolchain-event-pressure.md) 暴露的容量问题：详细解析关系耗尽额度后，后续模块加载仍可以记录。工具版本仍为 0.12.0；本轮不改权限搜索、恢复策略或最终验证要求。

## 保留什么，付出什么

加载事实回答“哪些模块、哪些已安装包留下了本次加载记录”；解析明细回答“哪个父模块把哪个请求解析到了哪里”。两者不再共享一个停止开关。工作进程/线程各自使用下面的分配，仍受每份日志 10,000 个事件、2,000,000 字节和整次采集的总日志/字节上限约束：

| 通道 | 默认事件额度 | 默认字节额度 | 停止后影响 |
| --- | ---: | ---: | --- |
| 模块加载 loads | 6,000 | 1,156,684 | 后续加载不再记录，load_capture_status 保留缺口 |
| 解析与子进程启动明细 details | 3,872 | 771,124 | 后续解析/启动明细不再记录，加载可以继续 |
| worker 诊断 workers | 128 | 64,000 | 保持 v5 的创建/历史分配和有界父侧最终状态 |
| footer | 不计入事件 | 8,192 | 仍必须有有效结束记录才能判断该线程的采集健康度 |

事件额度合计 10,000，字节额度合计 2,000,000，均没有提高。实际 header 也占日志总字节，运行时同时检查总上限。更低的测试上限按相同比例分配，worker 和 footer 继续预留。

这是明确的取舍：保留更多加载事实，解析图可能更早停止。没有把解析图压缩成完整关系的替代品，也没有过滤工具链依赖。6,000 个独立加载仍可能不足；这一版解决两种事实互相阻塞的问题，不提供无界记录。

## 状态与保存材料

- load_capture_status 与 load_issues 描述加载通道；resolution_capture_status 与 resolution_issues 描述解析/启动明细通道。
- 原 module_capture_status 和 capture_status 继续保留综合健康度。解析明细不完整时整体仍不完整，退出码没有放宽。
- 缺 footer、损坏记录、I/O 故障、日志总上限和 worker 诊断缺口会影响两类状态；只耗尽解析明细时，不把正常保留的加载通道也标为触顶。
- trace_diagnostics.budget / channels 新增可选 loads。旧 v5 的共享通道没有独立加载健康度，旧报告读取器兼容路径不会替它补造新状态。
- 模型的 modules 来源、包查询的 Node 列和终端的 Node 加载状态使用明确保存的加载状态，旧材料回退到原状态。解析关系另列自己的状态，整体分析仍保留相应缺口。

采集完成限定在可读的受仪器记录的进程/线程及钩子范围。原生工具、清空 preload 的子进程、任意文件读取等原覆盖边界保持不变。子进程启动明细也受 details 额度约束；明细停止后的无记录不代表没有子进程。

加载与解析继续共用 interned-v1 字符串字典，以保留路径和请求。只有成功写入的事件才提交新字符串编号；一个被拒绝的解析事件不会留下虚假编号供后续加载引用。定义随事件写入，损坏/中断日志只保留有效前缀。原始读取核对各通道计数、字节和 footer；保存报告读取拒绝超额、不一致或把有缺口状态改为完整的材料。

新增 22 个已记录包实例包括 @typescript-eslint/project-service、@typescript-eslint/typescript-estree、ajv 等。更多加载记录与更少解析关系符合本轮分配的取舍，不能把事件总数下降解释为项目工作量减少，也不能据此推导运行提速。

辅助 AVA worker 仍缺自身 footer；父侧记录 worker_unref_at_parent_exit。因此整个任务的加载和解析状态仍为 incomplete，CLI 返回 2。主线程有效 footer 说明其加载通道没有记录到额度耗尽；不能由此补出辅助线程的结束记录或完整加载总数。

旧材料位于本机 permstest/obs-one/usage.json；新材料位于本机 .permsift/toolchain-budget-v6/usage.json、usage.md 及对应原生执行/任务证据。原始材料未纳入源码仓库，本篇记录核对结果，不是完整原始报告或权限基线。本次工作流实测约 18.68 秒，1 次任务，0 安装，0 搜索；没有为同一观察结果反复运行全项目 lint。

## 验证范围

新增小型实际 Node 工作负载分别耗尽解析事件和解析字节，然后加载一个此前没有记录的包；核对加载仍保留、字符串字典可读、各通道与总上限。另覆盖加载额度耗尽、保存计数/状态篡改和 v5 原始/保存材料兼容。原 worker、同步退出回调、缺 footer 和损坏字典用例继续运行。

真实沙箱增加一个相同压力的任务，验收任务和边界通过、后加载事实保留、原生来源身份及在线/离线解释一致。默认 CI 的新集成总数为 83（原 82 加本用例），没有改变旧测试参数或搜索语义。完整测试结果与远端状态另见本轮 CI 记录。
